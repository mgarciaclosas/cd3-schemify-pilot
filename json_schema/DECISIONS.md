# Decisions — UK Generations Study R0 Questionnaire (schemify pilot)

- D001 · 2026-08-21 · package · missing-value sentinels: -999 for numeric/coded fields, "MISSING" for string fields, meaning "missing, no further distinction recorded" · BaselineMetadata.xlsx's Answers sheet defines no dedicated missing-value code for the majority of fields (empirically checked: of 685 properties audited across the wider GS schema family, ~79% have no distinguishing sentinel beyond bare null); -999/-1/999/9999 are already used elsewhere in this schema family for other specific meanings, so a distinct, previously-unused value was chosen to avoid collision · agent-decided · active
- D002 · 2026-08-21 · package · three additional sentinels adopted verbatim from the source: dont_know (AnswerID=3, 49 uses study-wide), dont_remember (AnswerID=5, 6 uses), not_applicable (AnswerID=6, 9 uses) · found by grouping BaselineMetadata.xlsx's Answers sheet by its harmonised AnswerID column (not the per-question AnswerCode, which varies by question) · user-confirmed (2026-08-21, steward pointed out the AnswerID harmonisation directly) · active
- D003 · 2026-08-21 · package · real data ruling: none of the pilot's fixtures use real participant data; toy rows are authored from the dictionary's value space per SKILL.md's radioactivity rule · steward has not offered real data access for this pilot · user-confirmed · active
- D004 · 2026-08-21 · package · companion flag-field pattern recognised: R0_GPdk (and similarly R0_ChildDOB_Unknown in CancerRelatives, checked as a second example) captures "don't know"/"not applicable" as a separate paired boolean field rather than an inline sentinel, used when the primary field is a date, name, or other free-entry type · confirmed by cross-referencing BaselineMetadata.xlsx's Questions/Answers sheets for both examples; all instances found so far are on AnswerDataType=integer companion fields · user-confirmed (2026-08-21) · active
- D005 · 2026-08-21 · general_information.StudyID · own local pattern ^[0-9]{6}$, not shared with the TCode pattern (^[A-Z0-9]{8}$) used elsewhere in this schema family (e.g. DerivedVariables_Schema.json) · description states "Unique 6-digit identifier"; verified these are different identifier concepts, not the same field under two names — an earlier draft of common/defs.json incorrectly assumed they were the same and was corrected before this category was finished · agent-decided · active
- D006 · 2026-08-21 · general_information.R0_LeftEducAge · plausibility maximum of 100 added to the numeric branch (source states minimum: 0 only, no maximum) · rejects the impossible, not the merely rare, per SCHEMA-PATTERNS.md; source is silent on an upper bound · agent-decided, open for steward confirmation · active
- D007 · 2026-08-21 · r0_questionnaire (mother file) · the R0_GPdk / R0_GP conditional is written as a skip-only rule (GPdk=1 -> GP pinned to the MISSING sentinel), with no paired applicability rule in the reverse direction · R0_GP has only one sentinel (the generic missing_string), not a dedicated structural-NA code distinct from ordinary non-response; a reverse "must not be MISSING when GPdk is not 1" rule would incorrectly forbid legitimate non-response for any other reason, so was deliberately not written · agent-decided · active
- D008 · 2026-08-21 · general_information · category-level ethnicity coding treated "0: More than one option chosen" and, for R0_EthnGroup, "9: None of these" as substantive answer codes, not missingness sentinels · confirmed via BaselineMetadata.xlsx: AnswerID=10 ("More than one option chosen") and AnswerID=4 ("None of these") are both distinct from the sentinel AnswerIDs 3/5/6 · agent-decided, low ambiguity · active
- D009 · 2026-08-21 · not-enforceable · uniqueItems (StudyID uniqueness across rows) cannot be exercised via tools/validate.py fixtures, which validates each toy_invalid row independently against the item schema and never applies array-level keywords · verified separately via a one-off tools/validate.py data run against a two-identical-row file, which correctly failed with keyword=uniqueItems · agent-decided · active
